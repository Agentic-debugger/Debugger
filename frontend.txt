  Project Summary (for context)                                                                                                                                                                                                                                                                                                                                                                               
  SP202 is a multi-agent pipeline that:                                                                                                                                                                  1. Detects bugs, security issues, and logic flaws in Python code (AST + Gemini LLM)                                                                                                                    2. Fixes them iteratively in a fix-validate loop (up to 3 passes)                                                                                                                                      3. Documents the entire process as a Markdown report                                                                                                                                                                                                                                                                                                                                                          Currently CLI-only. uvicorn is in requirements.txt — the backend is ready to expose a FastAPI REST layer.

  10. General UX Principles

  ┌────────────────────────┬──────────────────────────────────────────────────────────────────────┐
  │       Principle        │                             Application                              │
  ├────────────────────────┼──────────────────────────────────────────────────────────────────────┤
  │ Progressive disclosure │ Show summary first; expand for details (don't dump all data upfront) │
  ├────────────────────────┼──────────────────────────────────────────────────────────────────────┤
  │ Error transparency     │ Surface PipelineState.errors[] in a dismissible error banner         │
  ├────────────────────────┼──────────────────────────────────────────────────────────────────────┤
  │ Non-blocking UI        │ Long-running pipeline runs in background; user can navigate away     │
  ├────────────────────────┼──────────────────────────────────────────────────────────────────────┤
  │ Accessible severity    │ Never rely on color alone — use icons + labels for severity          │
  ├────────────────────────┼──────────────────────────────────────────────────────────────────────┤
  │ Keyboard shortcuts     │ Ctrl+Enter to run, Ctrl+D to download report                         │
  ├────────────────────────┼──────────────────────────────────────────────────────────────────────┤
  │ Responsive layout      │ Two-column on desktop, stacked on tablet/mobile                      │
  └────────────────────────┴──────────────────────────────────────────────────────────────────────┘

  ---
  Recommended Tech Stack for Frontend

  Framework:     React (or Next.js for SSR)
  Editor:        Monaco Editor (same as VS Code)
  Diff viewer:   react-diff-viewer or Monaco's built-in diff
  Markdown:      react-markdown + remark-gfm
  Charts:        Recharts (for error trend sparklines)
  Styling:       Tailwind CSS + shadcn/ui components
  Real-time:     Server-Sent Events (SSE) from FastAPI backend
  State mgmt:    Zustand or React Context

  ---
  Suggested Page/View Structure

  / (Home)
  ├── /run           → Input Panel + Pipeline Progress
  ├── /results/:id   → Detection | Fix History | Diff | Report tabs
  ├── /history       → All past runs list
  ├── /batch         → Batch upload & aggregate results
  └── /settings      → API key, preferences, theme

  ---
  The most impactful things to build first, in order:

  1. Input + Run trigger — connects directly to your existing pipeline
  2. Pipeline phase stepper + live progress — highest perceived value
  3. Findings table + diff viewer — core deliverable users care about
  4. Report viewer + export — completes the workflow loop
